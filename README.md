# Whisperoot (Chatroom web app for Software Studio Course midterm project)

A real-time chatroom web app with private group chats, built with React and Firebase.

## Highlights

* **Firestore data model with access control**: data is split into `user-data`, `group-data` and `group-list` collections, so that users can only read their own profile and the chatrooms they belong to.
* **Private group chats**: users create chatrooms and invite others by sharing a room code.
* **Browser notifications**: new messages trigger a notification when the chatroom tab is in the background.
* **CSS animations**: keyframe-based hover, list-expanding and message pop-out animations.
* **GIF search and sending** via the Tenor API (currently unavailable, see the note above).

## Functions required in spec

* Basic
1. Membership Mechanism
    * Email Sign In
        - When you haven't logged in, there is a "Login" button in the navbar at the top of the website. Clicking it directs you to the Login Page.
        - If you have registered an account, enter your email and password as hinted in the input boxes, then press the "Login" button.
        - If you haven't registered an account, click the "Don't have an account? Register now!" text, and the login page will switch to register mode.
    * Email Sign Up
        * After entering the register mode of the login page, enter your email, username, password and password confirmation as hinted in the input boxes, then press the "Register" button under them.

2. Host Firebase Page
    * The link to the Firebase page of this project is https://whisperoot-579d7.web.app/

3. Database read and write
    * I used Firestore instead of Realtime Database, since its document structure suits the functions of a chatroom better.
    * The Firestore database is divided into three collections: user-data, group-data and group-list.
        - The user-data collection stores user information such as email, username and group list. Each document is identified by the uid generated by Firebase Authentication, and users can only access their own user-data document.
        - The group-data collection stores messages and other content of chatrooms. Each document is identified by an 8-character UUID. Since the chatrooms are private, only members of a chatroom can access it.
        - The group-list collection stores chatroom information such as name, description and member list. Each document is identified by the same 8-character UUID as in group-data. All authenticated users can access it, since it is needed to determine whether a user is a member of a private chatroom.

4. RWD
    * The website works well when tested on my 17" notebook, common-sized smartphones and a 10.9" iPad Air. No content disappears unless the window is resized to an impractically small size.

5. Chatroom
    * After logging in, there is a "Chat" button on the navbar. Pressing it directs you to the chatroom page.
    * There is a sidebar on the chatroom page. Press the "Groups" button in it to expand your group list.
    * After expanding the group list, the groups you have joined are listed in the sidebar by name. Click one to enter that chatroom.
    * There are "Create a new group" and "Join a group" buttons under the group list after expanding it. Pressing them directs you to the corresponding page.
    * On the create group page, type in the name and description of your new group as hinted in the input boxes, then press the "Create" button. After the group is created successfully, you will be redirected to the new chatroom.
    * To invite other people to your chatroom, click the copy button beside the room code under the chatroom name. The room code is the group's UUID used in the database. Pass it to the people you want to invite, and they can join the group with it.
    * On the join group page, enter the code of the chatroom you received from the person who invited you, then press the "Join" button. After joining successfully, you will be redirected to the chatroom.
    * When you are in a chatroom, there is an input box for typing messages at the bottom of the page.
    * Click the send button (the paper plane icon) beside the message input, or simply press ENTER on your keyboard, to send a message.
    * Messages containing only whitespace are blocked automatically.
    * The placeholder hint in the message input changes randomly each time, just for fun.

* Advanced
1. Sign In/Up with Google
    * There is a button with the Google icon under the email/password Login button. Click it and log in to your Google account in the pop-up window.

2. Chrome Notification
    * When you log in or join a group, a notification welcomes you.
    * When the chatroom page is minimized or you switch to another tab, you will be notified when a new message arrives in the chatroom you have open.

3. CSS Animation
    * There is a "float" animation on buttons when you hover over them (not just a hover state; the transition is defined with keyframes).
    * There is a "pop" animation on items in the sidebar group list when it expands.
    * A new message "pops out" through a CSS animation that changes the size of its container.

4. Deal with HTML Insertion
    * Message content is rendered as plain text (inside a `<p></p>` element) through React's default escaping, rather than being inserted as HTML, so any HTML in a message is displayed as text instead of being executed.
    It didn't have any problem during my test.

* Bonus
1. Tenor API GIF sending
    * There is a GIF button beside the message input. Clicking it expands the GIF search area. Enter a keyword of more than 3 letters, and the first 8 related GIFs will be shown.
    * Click a GIF in the search area to send it to the chatroom.

## How to set up locally

1. Clone the repository:
    ```bash
    git clone https://github.com/laughtree/whisperoot.git
    ```
2. Navigate to the project directory:
    ```bash
    cd whisperoot
    ```
3. Install dependencies:
    ```bash
    npm install
    ```
4. Start the local dev server:
    ```bash
    npm start
    ```
5. Open the local website in your browser, and use it the same way as the deployed version.
